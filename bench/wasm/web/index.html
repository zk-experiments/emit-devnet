What is actually comparable?

Both registration cases use exactly the PR’s DSC → SOD → document → Emit registration application bytecode, fixture inputs, three link equalities and six public claims. The German document uses SHA-512 DG1 hashing; the US document uses SHA-256. No signer-chain or document-integrity check is omitted.

Chonk additionally folds registry/hiding kernels. Groth16 and ProveKit prove one merged application R1CS. Groth16 here is Arkworks—not Rarimo/Circom. ProveKit uses the common rc.5 ACIR-to-R1CS adapter and a full-R1CS non-SPARK verifier. Gates and R1CS constraints are different units.

The age check uses the US registration leaf in an Emit depth-32 identity tree, proves non-expiry and age ≥18 on the fixed fixture date, and returns a context-bound holder tag. Its public policy is shared across implementations. MRZ two-digit years use the most recent non-future birthday (ages 0–99); leap-day anniversaries use March 1 in non-leap years.

Proof bytes use actual serialization. Chonk includes pipeline/public fields; Groth16/WHIR public claims are external (192 bytes for registration, 160 for age). No separate PK-decoding measurements or additional key-validation pass are introduced. Key/runtime initialization is outside witness + prove. Each proving sample uses a fresh worker; full-device verification uses a separate verifier-only worker.
