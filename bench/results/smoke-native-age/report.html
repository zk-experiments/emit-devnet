Comparison boundaries

  • Chonk folds the application, registry and hiding kernels. Groth16 and ProveKit prove one merged application R1CS with the same cross-stage links. Circuit gates and R1CS constraints are different units. Shared Chonk structure counts use the WASM stats API only, outside all native measurements; no WASM proof or verification is run.
  • Groth16 is Arkworks, not Rarimo/Circom. ProveKit uses low-level WHIR over the shared rc.5 R1CS adapter, not its beta.26 Noir compiler. Its non-SPARK verification key includes the full R1CS.
  • Proof sizes are actual backend serialization. Groth16 raw/compressed encodings are shown separately; WHIR has no additional point-compression API (—). If proving fails, available sizes come from the native-generated proof accepted by independent verification. Chonk includes pipeline/public fields; Groth16/WHIR expected public claims are external: 192 bytes for registration, 160 bytes for age.
  • Memory is whole-process peak physical footprint, including native runtime initialization and keys, but excluding the coordinating Node process; RSS is also in JSON/CSV. Failed or wasm32-limited workloads remain unavailable, never zero or replaced with a smaller circuit.
  • Proving includes fresh witness generation; initialization is excluded from the prove timer, with no PK decode timer. Verification-only sessions load no unnecessary proving keys. Native full-host verification reuses a prepared native proof; no WASM proving or verification is executed.
  • 1 / 6 labels are backend worker budgets, not total OS thread counts; actual reported configuration is shown per row and in raw observations. Native MSM may create bounded nested pools. Native Groth16 streams its prepared matrix plan from r1cs.bin through BufReader during QAP; WASM uses a RAM-loaded plan.
  • Only synthetic passports and local test Groth16 setup. No live government trust, production ceremony or on-chain registration is claimed.
