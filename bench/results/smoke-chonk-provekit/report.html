Matched statements

German registration: Brainpool P384/SHA-384 DSC, Brainpool P256/SHA-256 SOD, SHA-512 DG1, followed by Emit registration. US registration: RSA-4096/SHA-256 DSC, RSA-2048/SHA-256 SOD, SHA-256 DG1, followed by the same registration. All implementations use the PR's exact application bytecode, fixture inputs, private link equalities and six public claims.

Age verification replaces member/payment experiments: the same US registration leaf, depth-32 membership, registration/document expiry, age ≥18 on 2026-09-27 and a scope-bound holder tag. It is a new shared circuit, not the PR's member_resolve or member_transfer.

Comparison boundaries

  • Chonk folds the application, registry and hiding kernels. Groth16 and ProveKit prove one merged application R1CS with the same cross-stage links. Circuit gates and R1CS constraints are different units.
  • Groth16 is Arkworks, not Rarimo/Circom. ProveKit uses low-level WHIR over the shared rc.5 R1CS adapter, not its beta.26 Noir compiler. Its non-SPARK verification key includes the full R1CS.
  • Proof sizes are actual backend serialization. Groth16 raw/compressed encodings are shown separately; WHIR has no additional point-compression API (—). Chonk includes pipeline/public fields; Groth16/WHIR expected public claims are external: 192 bytes for registration, 160 bytes for age.
  • Memory is whole-process peak physical footprint, including Node, runtime initialization and keys; RSS is also in JSON/CSV. Failed or wasm32-limited workloads remain unavailable, never zero or replaced with a smaller circuit.
  • Proving includes fresh witness generation; initialization is separate, with no PK decode timer. Verification-only sessions load no unnecessary proving keys. Full-host verification uses the same native-generated proof in WASM and native runtimes.
  • Only synthetic passports and local test Groth16 setup. No live government trust, production ceremony or on-chain registration is claimed.
